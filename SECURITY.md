# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in FAS through a public GitHub issue.

Use GitHub's private vulnerability reporting or security advisory mechanism for this repository when available.

If private reporting is unavailable, use the security contact configured in the repository's GitHub security settings.

When reporting a vulnerability, include:

- affected version or commit
- affected component
- security impact
- reproduction steps or a minimal proof of concept
- required privileges or conditions
- relevant logs or traces
- suggested remediation, if known

Do not include real credentials, customer information, or other sensitive data in a report.

## Scope

Reports may include issues in:

- analysis isolation and sandboxing
- evidence integrity
- authorization boundaries
- dependency handling
- tool execution
- API security
- data isolation
- unsafe command execution
- prompt-injection handling
- CI/CD configuration

## Supported versions

FAS is currently in early development. Version support will be documented when stable releases are established.

## Coordinated disclosure

We ask researchers to allow reasonable time for investigation and remediation before public disclosure.

Thank you for helping keep FAS and its users secure.
