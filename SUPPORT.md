# Support

Use the right channel for the type of request.

## Questions and usage

For usage questions, troubleshooting, and development help, search the repository documentation first:

- [README](README.md)
- [Architecture](docs/architecture/README.md)
- [Evidence Model](docs/evidence-model/README.md)
- [Threat Model](docs/threat-model/README.md)
- [Contributing](CONTRIBUTING.md)

If the answer is not documented, open a GitHub issue with enough context to reproduce the question or problem.

## Bugs

Open an issue at:

https://github.com/LloydCoder/fas/issues

Include:

- FAS version
- Python version
- operating system
- command or API request
- relevant configuration
- minimal reproduction
- expected behavior
- actual behavior
- sanitized logs or error output

Do not include credentials, customer information, private source code, or sensitive security evidence.

## Security vulnerabilities

Do **not** open a public issue for a security vulnerability. Follow [SECURITY.md](SECURITY.md) for private reporting.

## Feature requests

Before proposing a large feature, explain:

- the problem
- the affected users/workflow
- why existing capabilities are insufficient
- security and trust-boundary implications
- compatibility or schema implications

Small, concrete proposals are easier to review and evolve.
